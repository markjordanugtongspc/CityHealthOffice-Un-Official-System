System Setup & Usage

How you and your sister run this PHP + Vite system

Zero-terminal mode for your sister: On your sister's laptop, she only needs XAMPP (Apache + MySQL) running and a browser. No npm run dev, no PHP commands, no IDE.

1 What you must prepare (developer)

Prerequisites on your machine:

1. Install Node.js and run:
   npm install

2. Build production assets:
   npm run build

3. Make sure these exist before you copy to another laptop:
   - dist/            → built JS/CSS from Vite
   - config/.env      → database credentials (not in git)

Create or update your config/.env:

DB_HOST=localhost
DB_USER=root
DB_PASS=
DB_NAME=cho_db
DB_CHARSET=utf8mb4

The PHP config config/db.php now reads from config/.env, so you never hardcode DB passwords in the codebase.

2 How your sister runs the system

On your sister's laptop (no programming tools needed):

1. Install XAMPP and make Apache + MySQL start automatically.
2. Create the database (import your SQL schema).
3. Copy the project folder (including dist/) into:
   C:\xampp\htdocs\Project
4. Create config/.env on her machine with her DB credentials.
5. Open a browser and go to:
   http://localhost/Project/

Because the Vite helpers check if the dev server is running, her laptop will automatically use the built files from dist/.vite/manifest.json. She never has to run npm run dev.

3 Same-network access (LAN)

Goal: Other devices (phone, another PC) use the system over WiFi or LAN.

Step A — find the PC's IP address:

1. Press Win + R, type: cmd
2. Run:
   ipconfig
3. Look for "IPv4 Address", e.g. 192.168.1.123

Step B — access from another device:

From another PC or phone on the same WiFi:
   http://192.168.1.123/Project/
Vite + PHP host detection (for dev mode): When you are developing with npm run dev, vite.config.js uses host: true so Vite listens on all network interfaces, and config/vite.php / config/vite_helper.php read $_SERVER['HTTP_HOST'] to build the correct Vite URL dynamically. This means other devices on the same network can load assets via your machine's IP without editing any IPs in code.
Service Worker scope: The sw.js file lives in the project root and is registered using the current path as its base scope (e.g. /Project/). Whether you hit the app as http://localhost/Project/ or http://192.168.1.123/Project/, the service worker attaches to that origin and caches pages for faster navigation on that device.
Firewall note: If other devices cannot connect, make sure Windows Firewall allows inbound HTTP traffic for Apache on port 80. For dev-only sharing of the live Vite server, also allow port 5173 and run npm run dev on the main machine.
